Este informe cubre un dia intensivo de trabajo enfocado en un rediseno integral de la interfaz del CRM bajo un nuevo sistema de diseno “composer-canvas” estilo ClickUp/Linear. Se rediseno el widget de detalle de tarea, el modal de crear tarea, el formulario de crear oportunidad, los tres widgets de agendar actividad y el inbox de notificaciones. Adicionalmente, se construyo un sistema de gradiente de urgencia en tiempo real (minutos, no dias) que avanza visualmente a medida que las actividades se acercan a su fecha limite, sin necesidad de recargar la pagina.

Hito Mayor: Sistema de Diseno Composer-Canvas + Gradiente de Urgencia en Tiempo Real

Se aplico un nuevo sistema de diseno unificado a los 5 formularios/widgets mas utilizados del CRM, pasando de cajas rigidas con labels y bordes a un lienzo tipo Notion/Linear donde el usuario escribe como si enviara un mensaje: titulo grande sin borde, pills para metadatos con popovers, toolbar inferior con campos secundarios y validacion reactiva (boton gris hasta llenar requeridos, rojo inline al intentar submit vacio). Paralelamente se construyo un sistema que hace que el color rojo de las cards avance visiblemente minuto a minuto a medida que las actividades se acercan a su fecha limite — con 5 niveles de “calor” por granularidad de minutos (de 14 dias hasta < 1 hora) y refresh automatico cada 60 segundos, sin que el usuario recargue la pagina.

1. Widget Detalle de Tarea (Rediseno ClickUp/Linear)

Nuevo Widget 1440px estilo ClickUp/Linear con Descripcion Protagonista
Se rediseno de cero el modal de detalle de tarea: ancho 1440px (landscape), header breadcrumb [Proyecto › Cliente], titulo H1 de 36px sin borde, descripcion de 16.5px con line-height 1.78 que fluye como texto directo (sin card), chips de relaciones (Tarea padre / Oportunidad / Drive), seccion de subtareas con barra de progreso + badge, chat-tray sticky al fondo con focus-ring azul y hint “⌘ Enter”, y sidebar con propiedades como botones (Estado con dot de color, Responsable con avatar, Fecha Limite, Prioridad). Todos los IDs originales preservados para no romper los handlers existentes.
Mejora CTA “Completar tarea” Explicito + Menu 3-Puntos
Se reemplazo el checkbox 28x28 del titulo por un boton verde explicito “Completar tarea” con gradient emerald, sombra y hover lift estilo Stripe/Linear. Al completarse, swap a pill “✓ Completada” + boton “Reabrir tarea”. El icono de copiar enlace del header se reemplazo por un menu 3-puntos con dos acciones: Copiar enlace de vista previa (genera link firmado Django signing, sin migracion) y Eliminar tarea (solo creador / superuser). Se anadio una vista publica /app/shared/tarea/<token>/ que renderiza la tarea en modo read-only sin requerir login.
Mejora Fecha Inteligente + Empty States World-Class
La fecha limite en el sidebar ahora muestra una segunda linea meta tipo “Vence en 2 dias” / “Vencida hace 3h” con color automatico (rose si vencida, amber si <24-3d, neutral si +). El empty state de subtareas paso de texto gris plano a una card dashed horizontal con icono + “Anadir subtarea · Divide la tarea en pasos”. La lista de participantes y observadores se cambio de avatares circulares apilados a filas verticales avatar + nombre con boton de remover on-hover.

2. Crear Tarea (Composer Estilo Mensaje)

Nuevo Modal 1240px Tipo Mensaje con Pills + Popovers
El formulario denso anterior (titulo compacto + 10 campos en grid con labels tipo NOMBRE / FECHA / INICIO / FIN / DESCRIPCION / PARTICIPANTES / OBSERVADORES / PRIORIDAD) se reemplazo por un lienzo composer: header con pill de oportunidad dinamica (fetch desde API al abrir), titulo 34px, descripcion 16px / min-height 360px que fluye sin borde, y toolbar inferior con pills (Estado / Responsable / Participantes / Observadores / Prioridad / Fecha) que abren popovers con los buscadores existentes. Labels dinamicas: “Participantes · 3”, “17 abr · 13:38”, “Alta”. Atajos ⌘/Ctrl+Enter para enviar.
Mejora Adjuntos Habilitados + Oportunidad en Header
El icono paperclip se activo: al clicar abre file-picker multi-archivo y los archivos seleccionados se muestran como chips pill bajo la descripcion (nombre truncado, tamano KB/MB, boton de quitar). Al crear la tarea, los adjuntos se suben como comentario inicial reutilizando el endpoint existente — sin necesidad de migracion. El header ahora muestra el nombre de la oportunidad vinculada (o “Sin oportunidad”) en lugar del proyecto, haciendo fetch a /api/oportunidad/<id>/detalle/ al abrir el composer.

3. Crear Oportunidad (Composer + Validacion Reactiva)

Nuevo Canvas con “Para [Cliente]” en Lenguaje Natural
Se rediseno el formulario denso anterior (10 campos en grid con monto manual) a un lienzo con titulo 34px, fila “Para [Selecciona un cliente (requerido)]” con pill dashed que abre popover con autocomplete + crear-nuevo inline, pills Tipo (requerido) y Cierre (requerido) con popovers de select, textarea de notas, y toolbar con ghost buttons (Contacto / Producto / Area / Probabilidad). El monto se removio del formulario: ahora lo calcula el sistema automaticamente desde las cotizaciones.
Nuevo Validacion Reactiva Gris → Azul + Rojo Inline
El boton “Crear oportunidad” inicia gris (slate-200 / text-slate-400) y solo se vuelve azul (gradient + sombra) cuando titulo + cliente + tipo + cierre estan todos llenos. Si el usuario clica en gris, se previene el submit y las pills faltantes se marcan en rojo (soft-error con border dashed rose + bg) con animacion shake 320ms. Se agrego novalidate al form y se removieron los atributos required para eliminar los tooltips nativos naranjas del browser. Defaults limpios: pipeline solo Runrate/Proyecto (sin prospeccion), probabilidad 20% default, el resto vacio.

4. Agendar Actividad (Composer en 3 Widgets)

Nuevo Mismo Diseno en 3 Contextos (Oportunidad / Calendario / Prospecto)
Los 3 widgets de agendar actividad (widgetOppCrearActividad, widgetGlobalCrearActividad, widgetProspectoActividades) compartian diseno denso. Se unificaron al mismo composer-canvas con CSS compartido .wact-*: header breadcrumb, titulo 28px, fila natural [📅 Fecha] de [🕐 Inicio] a [🕐 Fin] con pills que abren popovers de <input type="date"/"time">, textarea de detalles, y toolbar con pill Participantes. Se crearon helpers globales wactOpenPop / wactValidate / wactTrySubmit y MutationObservers por widget. Todos los IDs originales preservados.
Mejora Autofocus + Hora Actual con Minutos al Abrir
Al abrir cualquiera de los 3 widgets: autofocus automatico en el input de titulo (el cursor queda listo para escribir) y las horas se precargan con la hora actual completa, incluyendo minutos (16:44, no 16:00). Fin = Inicio + 1 hora con rollover correcto a medianoche. Gate de “modo edicion” en el calendario para no sobrescribir valores existentes.
Fix Sync Inline Postit/Kanban/List al Crear Actividad
Al crear una actividad, las cards SSR del postit + kanban + list-row mostraban “Sin pendientes” hasta recargar la pagina. La causa raiz: Django con USE_THOUSAND_SEPARATOR renderiza IDs ≥ 1000 como data-opp-id="1,198", pero mi selector buscaba "1198" sin match (mismo bug que el toggle-pin resolvio normalizando IDs). Se anadio _woNormId(s) que strippea espacios/nbsp/comas y se itera comparando el dataset normalizado. Ahora las cards cambian instantaneamente al crear la actividad.

5. Notificaciones (Inbox Estilo Linear + Agrupacion Inteligente)

Nuevo Rediseno Inbox Flat-List (Sidebar slate-50 + Feed)
Se redisenaron las notificaciones manteniendo el mismo tamano (94vw x 92vh): el header global con icono se eliminio, “Notificaciones” vive en el titulo del sidebar slate-50 (240px) con filtros planos (Todas, No leidas, Criticas rojo, Tareas, Oportunidades, Equipo, Admin) con badges circulares. El main area tiene “Bandeja de entrada” en header 52px + boton “Marcar todo como leido” + X. Las filas son planas (no cards) separadas por border-bottom con avatar 28x28 (iniciales color-deterministas por remitente o icono Sistema), unread-dot azul absoluto a la izquierda, y hover muestra botones de accion ocultando la hora.
Nuevo Agrupacion Inteligente por Objetivo + Simplificacion de Texto
Runs de 3+ notificaciones que refieren al MISMO objeto (misma tarea_id / misma oportunidad_id) se colapsan en un cluster expandible con badge contador — util para “5 comentarios en la misma tarea”. Notificaciones de diferentes objetos con titulo generico igual (ej: 5 “Tarea asignada automaticamente” para 5 opps distintas) se mantienen como filas individuales. Paralelamente, un simplificador de texto extrae “en la oportunidad X” y “al pasar a etapa Y” como chips de contexto, quita el prefijo “Sistema” redundante, y compacta verbos: “Se creo la tarea X” → “Se creo: X”. Menos ruido, mas velocidad de lectura.

6. Gradiente de Urgencia en Tiempo Real

Nuevo 5 Niveles Warm por Granularidad de Minutos
Antes el gradiente rojo de “vence pronto” tenia solo 3 niveles por dias (warm-1/2/3) — una tarea que vencia en 2 minutos se pintaba igual que una que vencia en 23 horas. Se extendio a 5 niveles por minutos: warm-1 (7-14 dias) → warm-2 (2-7d) → warm-3 (12-48h) → warm-4 (1-12h) donde el rojo ya cubre >2/3 del strip → warm-5 (≤1h) casi totalmente rojo. El backend calcula minutos_hasta_proxima con agregaciones Min() (sin N+1) y el frontend recomputa la clase via _pickWarm(minutos).
Mejora Refresh Automatico cada 60 Segundos (Sin Recargar Pagina)
Se agrego un setInterval de 60s que llama a refreshCrmTable() automaticamente cuando el usuario esta en la vista CRM. El sync reactivo borra las clases heat/warm existentes y re-aplica la correcta segun los minutos actuales devueltos por el API — asi el rojo avanza visiblemente minuto a minuto a medida que las actividades se acercan a vencer, sin que el usuario recargue. Se fixeo tambien un bug previo donde el sync borraba las clases warm-* incorrectamente al interpretar erroneamente que “no vencida = no hay urgencia”.

7. Sidebar + Ajustes Menores

Mejora Label Sidebar: “Alertas” → “Notificaciones”
Se renombro el boton del sidebar izquierdo de “Alertas” a “Notificaciones” para consistencia con el titulo del widget y el vocabulario que usa el equipo. Afecta tanto el label visible como el data-tooltip que aparece en hover.
Fix Overlay Custom para Confirmar Eliminacion de Tarea
El window.confirm() nativo del browser al eliminar una tarea se reemplazo por un overlay custom dentro del modal: backdrop slate/45 + blur 2px, card 380px con icono rose circular, titulo con el nombre de la tarea entre comillas, y botones Cancelar / Eliminar tarea (gradient rose con estado loading “Eliminando…”). Se cierra con ESC o click fuera. Experiencia mucho mas pulida que el confirm nativo del SO.
Fix Auto-Refresh Tabla CRM al Crear Actividad desde Oportunidad
Al crear una actividad desde el widget de oportunidad, solo se refrescaba la lista interna del widget. La tabla/kanban principal del CRM quedaba con “Sin pendientes” hasta recargar. Ahora tras el success de woCrearActividad tambien se llaman window.refreshCrmTable() y window.recargarTareasCRM() + _woSyncCardsWithActividad() que parchea el DOM de las cards SSR inmediatamente. Cambios instantaneos sin reload.
